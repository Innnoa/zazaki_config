## Grill-Me 协议

### 作用

定义 AI 在需要用户决策时的单问推荐交互协议。本协议是行为规范，不绑定到特定 skill——任何需要用户决策的流程均可引用。

### 五条核心规则

1. **一次一问** — 每次只问一个问题，等待用户反馈后再继续。一次问多个问题会导致认知过载。
2. **环境优先** — 如果事实可以通过探索环境得到（文件系统、代码库、工具等），先查找，不提问。决策权属于用户——逐一提交并等待回答。
3. **每问带推荐** — 每个决策点都要给出推荐答案和简要推理。
4. **深度优先遍历** — 沿决策树下行，依次解决依赖关系再回溯。先走完一条分支的子决策，再处理兄弟分支。
5. **硬门禁** — 在用户确认达成共识之前，不执行任何实质性操作。

检验：当前只有一个决策点未解决吗？下一个决策是否需要先完成当前决策链才能有意义地讨论？

### 触发条件

满足以下任一条件时启动本协议：
- 用户说"grill me"、"interview me"、"帮我理清"、"逐个确认"
- 当前流程进入需要用户决策的阶段（设计取舍、架构选择、范围界定）
- brainstorming 的提问阶段、writing-plans 的结构性决策、fix-and-review 的取舍判断

### 流程

1. **勘探** — 静默探索环境，收集事实。读相关文件、配置、代码结构。不问能查到的内容。
2. **构图** — 识别根决策及其分支。从杠杆最高的决策点开始。
3. **访谈** — 一次一问，每问带推荐：
   - 明确陈述决策点
   - 提供推荐答案和推理
   - 请求确认或替代方案
4. **沿分支深入** — 决策做出后，先深度优先跟随其子决策，再回溯到兄弟分支。
5. **确认闭环** — 决策树穷举后，汇总所有决策，询问："是否达成共识？可以继续吗？"

### 问题格式

```
**Decision: 待决策事项**

Recommended: 推荐方案
Reason: 推理和权衡

你的选择？
```

### 与其他流程的接口

- **brainstorming** — 在"Ask clarifying questions"阶段遵循本协议
- **writing-plans** — 在文件结构、架构取舍、任务分解等结构性决策点遵循本协议
- **fix-and-review** — 在需要用户权衡的修复策略选择时遵循本协议
- **skill 入口** — `skills/grill-me/SKILL.md` 作为用户直接入口，激活后遵循本协议

### 与 intuition-probe 的关系

- grill-me 访谈设计者，锁定"我要什么"
- intuition-probe 访谈 LLM（代表用户群直觉），验证"市场会默认伸手拿什么"
- 组合链路：grill-me 锁定设计决策 → intuition-probe 盲测验证直觉性 → 偏差处优先对齐到 LLM 猜测

### 检验句

问自己：`当前只有一个决策点未解决吗？下一个决策是否需要先完成当前决策链才能有意义地讨论？`
