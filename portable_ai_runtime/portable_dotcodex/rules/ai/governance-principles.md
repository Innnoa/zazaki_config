## AI 治理原则

### 作用

本文件只记录这套 AI 治理系统最值得长期保持稳定的少数原则。

它不替代 `routing-rules.md`、`recording-rules.md`、`task-closure.md` 或各类 workflow 细则，只作为长期不应轻易漂移的上层约束。

### 1. 路由单一权威源

- 任务路径判定细节只认 `rules/ai/routing-rules.md`
- `AGENTS.md` 只保留顶层触发意图
- 设计文档、reference 和 trigger phrase 文件只保留摘要、示例或人工校对用途

### 2. 非琐碎任务必须闭环

- 没有经过验证、AAR 四问和记录位置判断的非琐碎任务，不算完成
- 四问全部为“没有”时，也要明确写出“本次无新增规则或坑点”

### 3. 同一结论只保留一个主落点

- 默认只写一个主落点
- 其他文件最多加一句回链，不做全文重复记录
- 不允许把同一结论在 `CURRENT_TASK.md`、`DECISIONS.md`、`AI_GUIDE.md`、`references/ai/*` 中重复铺开

### 4. references 必须稀疏且真实

- `references/ai/*` 只收真实高价值样本
- 没有复发价值、没有明显成本、或单看代码就能看出来的内容，不进入 reference
- reference 不是聊天残渣存放区，也不是大而全知识库

### 5. trigger wording 必须持续对齐真实表达

- skill `description`、`AGENTS.md` 的自动触发语句、`routing-rules.md` 的路径条件，应持续围绕真实用户表述收紧
- 发现高频真实表述命不中时，先补样本，再调 wording，再判断是否要调路由
- 不为了通过单条样本把整体触发规则写得过宽

### 6. 能力并存时先定分工，再定路由

- 当同一能力在不同层同时存在时，先明确职责边界，再把它们接入路由和 workflow
- 对当前环境，OpenCode 原生 LSP 与 `serena` 不应被混写成一个模糊的“LSP 能力”
- 原生 LSP 负责诊断反馈与显式 LSP 查询，`serena` 负责语义级代码理解和结构化操作

### 7. subagent 派发层与用户交流层分离

- 面向用户的主 agent 输出、治理文档与状态文件默认保持中文
- 面向 subagent 的派发 prompt、任务边界、约束、输出格式默认使用英文
- 如果没有用户的相反要求，不要把主 agent 的中文交流约定直接复制到 subagent 派发层

### 8. 会话纪律必须显式重置

- 同一会话中的每个新任务都必须重读顶层路由入口，并重新匹配任务路径
- 长会话、压缩和任务类型切换都应触发显式重路由
- 不得把“刚读过”“这次很小”“先做再补路由”当成可接受的例外

### 9. 激活优于存储

- 高代价经验、闭环规则和会话预算规则，不能只存在于深层 reference 中；必须同时出现在正常任务路径能自然读到的位置
- 如果某条规则只有在人工翻 reference 时才能看到，则它还不算真正接入治理系统
- 因此高频提醒或高代价约束应至少落到以下一层：`AGENTS.md`、正式 `rules/ai/*`、或任务 workflow 的完成检查项
