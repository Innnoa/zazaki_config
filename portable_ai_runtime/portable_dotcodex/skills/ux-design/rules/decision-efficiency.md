# 决策效率层

## Hick's Law（希克定律）

选项越多，决策越慢。决策时间随选项数呈对数增长。

检验：关键页面的选项数是否 ≤ 7？是否有推荐/预选来减少用户决策？

- 导航一级菜单 5-7 个，其余折叠
- 定价页 3 个套餐最佳，标注推荐
- 复杂筛选分级：先大类再细分
- 表单预填默认值

## Fitts's Law（菲茨定律）

目标越大越近，点击越快。按钮尺寸和距离决定操作效率。

检验：所有可点击元素最小触摸区域 ≥ 44px？主要 CTA 是否放在拇指热区？

- 移动端触控区 ≥ 44×44pt (iOS) / 48×48dp (Material)
- 视觉尺寸可以小，可点击区域要大（padding 放大）
- 底部 Tab Bar 比顶部导航点击完成率高 20-30%
- 危险操作远离高频区域，变小变远
- macOS 菜单栏贴顶 = 垂直方向"无限大"目标

## Doherty Threshold（多尔蒂阈值）

系统响应 <400ms 时用户生产力最高。

检验：关键交互（点击/切换/展开）反馈时间 <400ms？长时间操作是否有进度条？

- 按钮点击、下拉展开、文字输入、开关切换 → 必须 <400ms
- 页面加载 <2s，搜索结果显示 ±1s
- 1-3s 等待 → 加 spinner/skeleton；3-10s → 进度条+百分比；>10s → 后台运行选项
- 骨架屏、乐观更新、预加载可提升感知性能

## Pareto Principle（80/20 法则）

80% 效果来自 20% 功能。把精力集中在高频功能上。

检验：是否知道用户 80% 的时间花在哪些功能上？核心功能是否占据最优先位置？

- 20% 核心功能占 80% 点击量 → 放在最显眼最大最快的位置
- 50% 边缘功能只占 5% 点击量 → 折叠/隐藏/收进设置
- 分析数据找到真正的 20%，凭直觉猜往往不准

## Choice Overload（选择过载）

选项过多导致决策瘫痪——用户不是选得慢，而是直接放弃选择。

检验：关键决策点的选项是否 ≤ 5？是否有推荐选项帮用户快速决定？

- 选项少 = 购买转化更高（果酱实验：6种 > 24种的 10 倍转化）
- 定价页 3 个套餐是最佳结构
- 用"推荐""最受欢迎""智能排序"帮用户聚焦
- 与 Hick's Law 互补：选项多 → 决策慢（Hick）+ 可能放弃（Overload）

## Occam's Razor（奥卡姆剃刀）

能用一个按钮解决的别用两个。选最简单的方案。

检验：每个元素都有存在理由吗？任务流程能再少一步吗？

- 每多一步，转化率下降 10-20%
- 流程 ≤ 3 步最理想，6 步以上用户开始流失
- 文案删到最短仍能表达清楚
- 简单≠简陋：简单是只保留必要的并做好每一件

## Parkinson's Law（帕金森定律）

不给用户设边界，用户会无限制地花时间——结果反而不满意。

检验：输入框是否需要合理字符限制？是否有适度时限促进决策？

- 输入框给字符限制（简介限 160 字）→ 信息质量更统一
- 限时优惠/倒计时 → 促使用户做决定
- 适当的约束提升体验，不是限制自由
