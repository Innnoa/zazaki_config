## Session Budget Rules

### 作用

统一记录当前会话 token 预算阈值、提醒语义和适用边界，避免在多个规则文件里出现第二套阈值。

### 当前阈值

- `100000 tokens`：预警阈值
- `150000 tokens`：强提醒阈值

### 触发语义

- 当会话上下文达到或超过 `100000 tokens` 时，应提醒用户准备开启新会话，并收缩非必要展开
- 当会话上下文达到或超过 `150000 tokens` 时，应在每次对用户的最终回答结尾追加固定提醒：`上下文已超过 150000 tokens，请开启新会话。`

### 适用边界

- 这是治理层的统一规则，不等于 host 已经提供了强制门禁或自动弹窗
- 如果当前运行面只显示上下文 token 信息、但没有可编程 hook，则执行方式仍以 agent 在最终回答中的显式提醒为主
- 如果后续 host 提供可编程 hook、pre-send gate 或自动后缀注入能力，再把运行时硬门禁细节升级到对应配置或脚本，不在本文件提前虚构

### 激活要求

- 本规则不能只停留在 reference；顶层入口和正式规则必须有最小锚点
- 新任务重路由、完成前验证、长会话提醒，这三类路径至少要有两类能自然读到本规则

### 检验句

- 问自己：`如果用户现在发来第 N 轮新请求，我会自然重新路由，并在超过阈值时自动加上对应提醒吗？`
- 如果做不到，不要声称该规则已经真正接入治理系统
