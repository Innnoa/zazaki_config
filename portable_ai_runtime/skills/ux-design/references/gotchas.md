# UX 法则常见冲突与坑点

## 跨法则冲突

| 场景 | 冲突法则 | 解决 |
| --- | --- | --- |
| 想给用户更多选择 vs 简化界面 | Hick's Law / Choice Overload vs 功能完整性 | 渐进式披露：先展示核心 20%，高级功能折叠。不砍功能，砍展示。 |
| 遵循平台惯例 vs 品牌差异化 | Jakob's Law vs 品牌识别 | 保持结构一致（布局、交互模式），在视觉风格（颜色、字体、插图）上差异化。 |
| 极简设计 vs 新手引导 | Occam's Razor vs Paradox of the Active User | 空状态教学 > 引导教程。界面自解释 > 弹窗说明。 |
| 视觉简洁 vs 信息可发现性 | Law of Prägnanz vs 功能可见性 | 常用功能直接可见，次常用在二级菜单，高级功能在设置/命令面板。不牺牲可发现性追求"干净"。 |
| 突出 CTA vs 页面平衡 | Von Restorff Effect vs 视觉和谐 | 一个页面最多 1-2 个突出元素。用"弱突出"（大小/粗细差异）替代"强突出"（对比色/动效）。 |
| 宽容输入 vs 数据质量 | Postel's Law vs 精确性需求 | 分层：前端宽容接收，后端严格校验。必须精确时（身份证）用实时校验+格式提示，而不是提交后报错。 |
| 进度激励 vs 制造焦虑 | Goal-Gradient / Zeigarnik Effect vs 用户体验 | 温和激励（"75% 完成"），不强制（"不填完不能用"）。未完成提示 ≤ 3 个。 |
| 消化复杂度 vs 用户控制感 | Tesler's Law vs 控制感 | 自动完成可选操作（智能默认值），保留用户可覆盖的余地。不要替用户做不可逆的决定。 |

## 常见错误

### 1. 过度依赖单一法则

例：只看 Occam's Razor 砍掉了所有"非必要"元素 → 违反了 Mental Model（用户找不到预期功能）。

**每做一次减法，至少检查一次 Mental Model 和 Cognitive Load。**

### 2. 忽视"负峰值"

大多数团队只关注正峰值（"哇"时刻），忽视了负峰值（支付失败、App 崩溃、数据丢失）。一次负峰值需要 3-5 次正峰值才能抵消。

**优先级：消除负峰值 > 创造正峰值。**

### 3. 默认值缺失

现状偏误（Cognitive Bias / Status Quo Bias）意味着大多数用户不会改默认设置。如果默认值不好 → 大多数用户获得差体验。

**好的默认值是最低成本的 UX 优化。**

### 4. 把法则当教条

"Miller's Law 说 7 个，所以导航必须 7 个"——这是误用。5 个比 7 个更好，结构化分组比死守数字更重要。

**法则是指南，不是圣经。用检验句判断，不用数字绑架。**
